# Peyton — cleaning decisions

1. **Scope:** Use every row and all 35 fields in `ratings-00007.tsv`. Earlier one-week results are historical and are not the current prepared dataset.
2. **Source preservation:** Read strings with automatic missing-value inference disabled. Keep the original TSV unchanged. Record its SHA-256; do not infer download date from modification time or observation cutoff from the latest event.
3. **Text:** Preserve original labels, IDs, leading zeros, suggestion text, and whitespace. A whitespace-only optional suggestion is counted as blank but retained. No evidence justifies automatic trimming, category regrouping, or rating deletion.
4. **Types:** Keep original milliseconds and add a UTC date and invalid-date flag. Invalid dates would remain as missing derived dates with flags. This does not change source columns.
5. **Duplicates:** Audit all 35 fields for exact duplicates and separately audit note/rater pairs, note IDs, and rater IDs across the complete file. Report duplicate groups, all involved rows, and excess rows separately. Repeated individual note and participant IDs are expected because each can appear in multiple ratings. No records are removed.
6. **Missing values:** Retain optional suggestion blanks. Count empty and whitespace-only values together when reporting blankness; do not interpret sentinel IDs as empty strings.
7. **Suspicious IDs:** Preserve flagged values and do not use unverified sentinel IDs as valid post/suggestion join keys. The official schema identifies `ratedOnTweetId` as the rated post ID and `suggestionId` as a collaborative suggestion ID, but does not establish the meaning of the observed negative sentinels. This interpretation remains unresolved. Source: [Community Notes download schema](https://communitynotes.x.com/guide/en/under-the-hood/download-data).
8. **Independent records:** Save five AI-assisted expectations before preparation. Derive expected dates using Python standard-library epoch arithmetic, then compare with pandas output read back from the saved CSV. Include blank text, whitespace-only text, a sentinel, nonempty text, and a leading-zero participant ID. This documents agent-assisted verification, not manual student work.
9. **Reproducibility:** Run the script from the original TSV, then all notebook cells in a fresh kernel. Compare SHA-256 hashes of all inspection/preparation CSV and JSON outputs. Preserve the input source hash and pinned dependency versions.
10. **Business limitations:** Ratings describe submitted activity in one downloaded shard. They do not establish platform-wide activity, first Helpful, broad agreement, or whether more ratings would cause a faster outcome. Response-time metrics still require appropriate status history, an agreed endpoint, and a verified cutoff.
